  why_it_matters: |

    会建议用户写"我们发布了 X / 支持长上下文 / 效果很好"这种公告式表达,
    这正是作者批判的反面案例。
    正确用法: 每条内容检查是否完成了三次视角转换,
    尤其第三次 (结论→证据) 是最常被跳过的。

    = 信任建立的三个可验证维度:
      - 可见 = 眼见为实 (不是描述而是展示)
      - 可点 = 路径可达 (不是空说而是能找到)
      - 可算 = 结果可量化 (不是"效果好"而是有数字)
    = 降低读者的"验证成本",从而提高信任与传播
  why_it_matters: |
    下游内容生产 skill 若只说"加证据",
    用户不知道加什么算证据。
    正确用法: 用三个可作为证据的具体标准,
    每条内容至少满足两个"可",尤以"可算"(数字/对比)最缺也最有效。

    泛流量路线选"传播+变现"放弃深度。

- id: g12
  term: 候选隔离 (candidate isolation)
  type: term
  source_chapter: "X推荐算法.md / Key Design Decisions — Candidate Isolation in Ranking"
  author_definition: |
    "During transformer inference, candidates cannot attend to each other—
    only to the user context. This ensures the score for a post doesn't depend
    on which other posts are in the batch, making scores consistent and cacheable."
  key_distinction: |
    ≠ 常识中"推荐排名 = 帖子之间互相比较分高低" — 恰恰相反
    = 排序时 transformer 中候选帖互不可见, 只 attend 用户上下文
    = 单帖评分独立于同批次其他帖, 分数稳定可缓存
    = 工程含义: 每条帖子的分数由"帖子内容 + 用户历史"决定,
      不受"碰巧和谁同批"影响
  why_it_matters: |
    下游算法推导 skill 借此说明:
    单帖评分是独立且稳定的, 创作者应关注"这条帖子和目标用户的相关性",
    而非担心"我的帖子会不会被同期大帖压下去"。
    这也解释了为什么长尾分布下, 提升单帖质量 (四省/五件套/三个可)
    能系统性提高进前 10% 概率。

  key_distinction: |

      - Quote = 基于别人的内容补充增量观点 ("我基于这个补充") → 展示你的思考
    = 新人应多用 Quote 而非 Repost:
      - Quote 让原作者看到你的观点, 可能互动 (点赞/回复)
      - Quote 给原帖增加曝光
      - 但 Quote 必须有增量价值, 不能只说"太强了" (会被当蹭流量)
    = 直接搬运别人内容而不 Quote 是最不尊重原创的, 容易被举报
  why_it_matters: |
    下游互动增长 skill 需要区分 Quote 和 Repost 的使用场景,
    若混为一谈, 会建议用户无差别转发,
    新人只 Repost 会导致"别人记不住你"。
    正确用法: 新人优先 Quote + 增量观点,
    Repost 仅用于纯推荐场景。
  tags: [term, interaction-strategy, distinction]
